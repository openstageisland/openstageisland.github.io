{%- comment -%} seo-head.html -- the ONLY place this site writes search metadata. Why this file exists at all, given jekyll-seo-tag was already doing this job: The site shipped a hand-written and <meta name="description"> in _layouts/default.html AND {% raw %}{% seo %}{% endraw %} a few lines below them. Both rendered, on every page, on all four sites. That is two <title> elements and two meta descriptions per URL, which is undefined behaviour: each engine picks one, inconsistently, and which one it picks is not something you control. The hand-written pair also ignored front matter, so it rendered the same string for the homepage and for all 17 tool pages. So this file replaces {% raw %}{% seo %}{% endraw %} entirely and owns the whole head: one title, one description, one canonical, one set of Open Graph tags, one set of Twitter tags, one JSON-LD graph. One writer means one answer, and check_seo.py can assert "exactly one" because there is only one place to look. Contract, enforced by scripts/check_seo.py: * exactly one <title> per page * exactly one <meta name="description"> per page, unique across the site * exactly one <link rel="canonical">, always absolute, always on site.origin * og:image and twitter:image always present and always a real PNG * the JSON-LD block always parses, and always has the site-level nodes Precedence for each field, highest first: title page.seo_title > page.title > site.title description page.description > <tool node description> > site.description canonical page.canonical > site.origin + page.url image page.image > <tool card> > site card from _data/seo.yml robots page.robots > "index, follow" `page.seo_title` is separate from `page.title` on purpose: the H1 wants the short brand ("LANScan"), and a SERP line wants the searchable phrase ("LANScan — LAN device scanner").
